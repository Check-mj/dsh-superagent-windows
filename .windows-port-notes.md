## 1. Files I changed / added (all under `scripts/`; no `src/` or `lib/` edits)

| File | Status | What it does |
| --- | --- | --- |
| `scripts/dsh-superagent` | modified | Same Python service manager, same CLI surface and exit codes. POSIX path is untouched (`os.name != 'nt'` keeps tmux, `ps`, `fcntl`, `os.kill(SIGINT)`). `os.name == 'nt'` takes a new branch: detached spawn, pidfile, named-pipe stop request. The health-wait loop was extracted to `wait_for_health()` and is now shared by both platforms (behaviour unchanged). |
| `scripts/dsh-superagent.cmd` | **new** | Windows entry point (batch, not PowerShell — execution policy blocks `.ps1`). Finds Python via `DSH_SUPERAGENT_PYTHON`, then `py -3`, then `python.exe`/`python3.exe`, verifying each with `-c "import sys"` so the Microsoft Store stub is skipped; then runs `dsh-superagent` with the caller's args and propagates its exit code. |
| `scripts/dsh-service-hook.mjs` | **new** | Preloaded into the service (`node --import <file>`) by the Windows `start`. Opens a named pipe and, on the line `stop`, emits the `SIGINT` event DSH already handles on Ctrl+C (stops Sessions, disposes the app). Inert unless `DSH_SUPERAGENT_CONTROL_PIPE` is set, so booting a profile by hand is unaffected. |

## 2. Windows operator commands (PowerShell, from the checkout root)

```powershell
.\scripts\dsh-superagent.cmd start
.\scripts\dsh-superagent.cmd status
.\scripts\dsh-superagent.cmd stop
.\scripts\dsh-superagent.cmd restart
.\scripts\dsh-superagent.cmd --profile superagent --respect-stop restart
```

Exit codes are unchanged: `0` healthy, `1` not running / duplicate / unreachable / runtime error (a restart may fix),
`2` running but another part errors (a restart will not fix), `3` running but waiting for setup (a restart will not fix).
`--profile`, `--url`, `--timeout`, `--stop-timeout`, `--respect-stop` are unchanged and also read `DSH_SUPERAGENT_PROFILE`
and `DSH_SUPERAGENT_URL`.

- Service command: `node --import <scripts\dsh-service-hook.mjs> <dsh lib\bin.js> --profile <profile> --no-open`, cwd = checkout.
  `dsh`'s entry point is found from `DSH_SUPERAGENT_DSH_BIN` (a `lib/bin.js` path, used for tests), else `dsh` on PATH,
  else `%APPDATA%\npm\node_modules\@deepseek-ai\dsh\lib\bin.js`.
- Logs: `.artifacts\dsh-superagent-<profile>-<YYYYMMDD-HHMMSS>-<pid>.log` (child stdout+stderr), newest 20 kept.
- Control files: `.artifacts\control\profiles\<profile>\` — `service.pid`, `manually-stopped`, `operation.lock`.
- Stop marker: only `stop` writes `manually-stopped`; `start` clears it; `restart` writes none. `--respect-stop` on
  `start`/`restart` exits 0 with "Intentional stop is active; automatic recovery skipped.".
- Liveness: `OpenProcess` + `GetExitCodeProcess` on the recorded pid (`service.pid`), then the management API
  `GET http://127.0.0.1:<port>/orchestrator/api/state` with `x-orchestrator-request: 1`. Never probe `/` (401 by design).
- Graceful stop: write `stop` to the named pipe `\\.\pipe\dsh-superagent-<profile>-<sha1(checkout path)[:8]>`, wait up to
  `--stop-timeout` (default 300 s) for the pid to exit; **no force kill is ever sent** — timeout raises the documented error.
- `start` refuses to launch when an orchestrator already answers at `--url`, and never starts a second instance for a live pid.

## 3. Windows facts for `src/` (verified by experiment; the Lead owns the edits)

1. **worker-bin shims.** An extensionless `#!/bin/sh` file is never found on Windows (PATHEXT), so `<name>` shims do nothing.
   Working form — one file per command, `gh.cmd`, `lark-cli.cmd`, `<blocked>.cmd`, **LF-only line endings** (a label-free
   batch body works fine with LF; CRLF would break `written()`'s exact first-two-lines comparison):
   ```batch
   @echo off
   rem Written by dsh-superagent on every start; edits are lost.
   setlocal EnableExtensions EnableDelayedExpansion
   set "SELF=%~dp0"
   set "SELF=!SELF:~0,-1!"
   set "OUT="
   for %%e in ("%PATH:;=" "%") do (
     if /I not "%%~e"=="!SELF!" set "OUT=!OUT!;%%~e"
   )
   set "PATH=!OUT:~1!"
   "C:\absolute\path\to\agent-cli.cmd" %*
   exit /b %ERRORLEVEL%
   ```
   Verified: the shim dir is stripped when first, in the middle, last, or absent in PATH, with a hostile PATH containing
   `C:\Program Files (x86)\Common Files` and `D:\a&b\dir`; the wrapper's name-based `gh` then resolves to the real `gh.exe`
   (one wrapper run, no recursion); `%*` keeps the caller's argv text (an arg with `&` inside quotes survives); a `.cmd`
   target transfers control so its exit code becomes the shim's (and `exit /b %ERRORLEVEL%` covers `.exe` targets).
   Blocked commands: `echo <name> is blocked in this installation; use gh, which acts as <login>. 1>&2` + `exit /b 1`
   (verified stderr text and exit code 1).
   `written()` needs a Windows marker: a first line beginning `#` would be executed by cmd.exe and print an error, so the
   marker must be `rem Written by dsh-superagent on every start; edits are lost.` and accepted **only on win32** (keep the
   existing exact list for non-win32 so Linux behaviour is unchanged).
2. **git credential helper: no change needed.** `credentialHelper()`, `gitQuote()`, the `worker-gitconfig` contents and
   `verifyEnvironment()` all work on Windows as written. Git for Windows runs `!`-helpers through its own `sh.exe`, so
   `helper = !'<absolute cli path>' auth git-credential` executed the wrapper with argv `auth git-credential get` and
   returned username/password (verified with backslash paths, forward-slash paths, and a path containing spaces). The
   `--show-origin` rendering is exactly `file:` + the path passed as `GIT_CONFIG_GLOBAL`, i.e. `file:D:\…\worker-gitconfig`
   matching `join(stateDir,'worker-gitconfig')` byte for byte → the exact-string comparison passes and `gitTooOld` does not
   fire. Dependencies: git 2.32+ **and** a git that ships `sh.exe` (Git for Windows / MinGit do).
3. **`.cmd` cannot be spawned without a shell.** Node ≥ 18.20 / 20.12 refuses `spawn`/`execFile` of a `.cmd`/`.bat` unless
   `shell: true` (CVE-2024-27980) — it throws `EINVAL`. So programmatic calls (`runAsWorker`, setup probes, `Commands.run`)
   must pass an executable (`.exe`) absolute path, or route a `.cmd` through `cmd.exe /d /s /c` with cmd-escaped arguments.
   The `.cmd` shims are only for what worker *shell* sessions invoke by name.
4. **prepare command** should be `['sh','-c',command]` on POSIX (unchanged) and `['cmd.exe','/d','/s','/c',command]` on
   Windows; Git-for-Windows `sh.exe` is not on PATH by default, so `sh` would fail. Consequence for the guide: the upstream
   POSIX `git fetch && git worktree add` example needs a cmd rewrite (`%DSH_SUPERAGENT_…%` instead of `$DSH_SUPERAGENT_…`).
5. **`workerProbe`'s `env PATH=…` prefix** does not exist on Windows; pass `env: { PATH }` in the spawn spec instead
   (verified that the dsh subprocess seam merges explicit env entries).

## 4. Residual Windows risks

- **Port 3082 is occupied on this machine** by PID 4844, which answers `/` with 401 but returns 404 for
  `/orchestrator/api/state` (a dsh webserver without the dsh-superagent plugin). A launcher `start` on the default profile
  will therefore fail to bind until that process is stopped or the profile port is changed; `status` reports exit 1.
- Graceful stop depends on `scripts/dsh-service-hook.mjs` being preloaded. A service started by an older copy of the script,
  or by hand without `DSH_SUPERAGENT_CONTROL_PIPE`, cannot be stopped by `stop`; it fails with an explicit message instead of
  force-killing. Restarting it with `start` fixes that.
- The named pipe is per user and per checkout path (sha1 of the checkout). Any local process of the same user could send
  `stop`; like the rest of dsh-superagent this is a guardrail, not a security boundary.
- `stop` waits for DSH's own graceful shutdown; a hung Executor makes it time out (documented 5 minutes) with no force kill,
  exactly like the POSIX version.
- `dsh` prints the panel URL with a token; nothing in the launcher opens a browser (`--no-open` is always passed).
- No admin rights and no Windows service registration: the service runs as the operator's user and does not survive logoff.
- Python 3.8+ must be on PATH (or `DSH_SUPERAGENT_PYTHON` set); without it `scripts/dsh-superagent.cmd` exits 1 with a message.
- The `--patch`/`--port` overlay used in the end-to-end test is a test artifact only; the launcher runs the documented
  `--profile <name> --no-open` command and takes the port from the profile configuration (`--url` only checks it).
